# 地圖移動後的附近景點更新

此分支以 main 為基礎，同時修正 iOS／Android 的探索地圖與行程首頁地圖。

## 原因

- 探索頁的鏡頭事件只保存中心位置，景點列表及自訂標記仍使用上次搜尋結果。
- 行程首頁原本只畫行程站點與路線，沒有在鏡頭移動後查詢附近景點；iOS 也關閉了原生底圖 POI，因而無法靠底圖補足標記。

## 新行為

- 鏡頭停下約 800 ms 後搜尋；快速連續移動取消過期請求，只採用最後位置。
- 移動超過約 60 公尺或縮放超過 0.35 級才重新排程，避免標記重繪產生循環請求。
- 依中心緯度與縮放估算搜尋半徑，限制 500–5000 公尺；這是附近搜尋，不保證涵蓋縮得很遠的整張視窗。
- 首頁以獨立標記更新附近景點，不把結果加入行程，也不因結果載入而重新縮放／置中行程。
- 點附近景點可看介紹；加入工具箱沿用明確加入按鈕。
- iOS Apple 底圖直接使用 MapKit，Google 使用 Google Places，OSM 使用原有開源服務。Zetaris 模式仍經既有後端取得地點，不改底圖及資料來源的選擇。
- 請求失敗顯示可重試提示；離線示意圖不查地點。Google 請求仍受既有金鑰及後端付費服務政策限制。

## 本次結果

iOS 102 項、Android 29 項單元測試與 1 項 Android 模擬器測試通過。iOS／Android 均已編譯並可啟動；Google 金鑰與實際付費 Places 請求未作端到端驗收。

## 資料範圍

本機 Overture／OSM 快照只有已匯入區域。拖到未匯入地區、來源無資料或超出後端可查範圍時，不能憑空產生景點。Apple／Google 搜尋也可能限制回傳筆數，標記並非所有商家的完整目錄。

## 驗證

- iOS：新增快速移動合併、過期結果取消、離開頁面取消查詢、附近標記更新不移動鏡頭且不選取行程站點的測試。
- Android：新增移動判定與半徑界限單元測試；模擬器測試注入地點資料，驗證只搜尋最後位置及標記更新不重查。
- 手動：在探索地圖／行程地圖拖到另一區，停下約一秒，確認新標記出現且鏡頭不回彈；點標記查看介紹。切換底圖／資料來源後再重做，確認沒有上一來源的結果混入。

本機開發與驗證，不含推送或合併 main。
