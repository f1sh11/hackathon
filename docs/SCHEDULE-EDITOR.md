# 客製化多日時間軸：本機原型

開發分支：`feat/personalized-schedule-editor`。iOS / Android 的既有問答畫面不變，問答後的 demo 草案進入新的直向時間軸。

## 操作入口

- 完成既有問答：demo 首版行程會開啟時間軸，不需要先手動勾選景點。
- 「行程 → 試用 3 天時間軸」：使用獨立示例建立 3 天草案，不必重走問答。
- 已保存 demo 行程點「編輯時間軸」：沿用行程與 revision，確認後才覆蓋保存。
- `live` / `assisted` 保留原草案流程；新編輯器刻意不混用其他來源內容。

## 已實作

- 按既有興趣與偏好產生 1–3 天首版，分配不重複景點。悠閒／適中／緊湊會改變選點數與停留時間。
- 可展開的五軸雷達圖；行程內微調每日／全程預算、步數、交通排隊額度、餐費、廁所間隔與行李需求。
- 直向活動卡：拖動把手換順序、拉下緣改停留、上移／下移替代操作、精確時間編輯、固定時段、移到其他日期、移除、還原及重新建議。
- 候選景點勾選與必去標記；手動順序在後端重算時保留。明確按「重新建議」才重選活動。
- 午晚餐時段（依可用活動時間）、廁所停靠與間隔檢查、住宿入住／退房、寄放／取件配對與位置檢查；也可手動新增生活活動。
- 每晚住宿座標、房費及入住／退房時間可編輯；更新住宿後重算相鄰天的起終點和依賴任務。僅計前 N−1 晚房費。
- 交通＋景點排隊額度與整天排程時間分開；交通包含全部轉場及返回，遊覽不直接扣主時間額度。
- 排隊可留空，或填入明確標示的使用者規劃假設；未知值不能聲稱尚有完整剩餘額度。
- 超過步數、每日／全程花費、交通＋排隊時合併提示；同一結果不反覆彈窗。
- 營業窗口檢查包含完整停留與排隊；固定時間、取件、入住或當天結束衝突阻擋保存。
- 下雨示例可標示戶外風險，室內候選提高排序；使用者可選替代地點或明確重新產生建議。
- 前端取消過期試算並保留最新草案；網路失敗可以重試。保存時後端再次計算，沿用 revision 防止過期覆蓋。PostgreSQL 不需新增表，編輯狀態保存在原 Trip JSONB。

## 共用契約

`POST /schedule/editor`

```json
{
  "trip": {"mode": "demo", "profile": {}, "days": []},
  "settings": {"pace": "balanced", "timeLimit": 180},
  "days": [],
  "version": 1,
  "rainy": false
}
```

這是欄位示意，`trip.profile` 仍須符合既有完整旅遊資料。首次省略 `days` 會自動選點；後續傳入 `schedule.days` 保留使用者活動順序與設定。回應是相容原客戶端的 Trip，附帶 `schedule`：

- `settings`：編輯器限制與偏好。
- `days[].activities`：活動 ID、種類、位置、停留、指定時段、費用、排隊假設與計算結果。
- `days[].stay`：每日住宿規劃，座標和房費。
- `issues`：問題代碼、所在日期／活動與是否阻擋保存。
- `candidates` / `radar`：排序後候選與偏好視覺化。
- `version`：前端草案計算版本；正式保存仍使用 Trip revision。

舊 `days[].stops` 與 `legs` 同步由後端產生，使既有地圖和行程列表可讀。生活安排也會顯示為站點。交通估算沒有線形，不會拿直線充當道路導航。

## 資料範圍與待辦

這版是本機單人示例原型，不是正式旅遊服務：

- 候選仍為 8 個已知悉尼地標，交通用既有距離估算；沒有新增真實道路／大眾運輸或票價提供商。原有獨立道路預覽仍可使用。
- 餐廳、廁所、住宿與寄放點先用待確認佔位；座標、服務時間和費用可手動修正，沒有查詢可用房間、寄放容量或訂位。
- 排隊資料未知；填入的是使用者假設，沒有真實即時排隊資料。天氣按鈕為測試情境，不宣稱取得即時預報。
- 金額為單人估算，未實作多人／多房分攤、跨幣別、跨午夜或過夜寄放。寄放與取件目前按每天配對，跨日不能默默丟失，需後續擴充跨日狀態機。
- 室內替代與重新建議是明確使用者操作，尚無背景天氣推播與只改受影響區段的最佳化。
- 時間軸活動高度為方便觸控的分段比例，有最小與最大高度；時間標籤才是準確值，尚未加入整日統一縮放或精確按分鐘定位的空白時間格。
- 不讀 GPS、不觸發外部付費呼叫、不自動訂房／付款。真實資料轉接可在已驗證的中立契約下逐步新增。

## 直向時間軸互動（參考稿調整）

- iOS 與 Android 使用相同的分鐘座標，卡片高度按停留時間比例顯示；左側每 30 分鐘標示刻度，可放大／縮小。
- 拖動右側 ☰ 保留停留長度，平移開始／結束時間，跨過其他活動後按時間排序。
- 上把手調整開始時間並保留原結束時間；下把手調整結束時間並保留原開始時間。以 5 分鐘吸附，停留限制為 5–240 分鐘；鎖定活動不能拖曳。
- 已知排隊與入站交通獨立占時間，不隨停留卡片縮短；未知排隊明確標示。上把手改動會一併平移該活動的排隊開始時間。
- 虛線空白區表示可保留的彈性時間；點擊開啟景點／生活安排清單。新增項目目前仍由試算服務安排，並非保證放進被點擊的空檔。
- 點卡片開啟原有的詳細編輯、移除、鎖定及跨日功能。拖曳後重新試算交通、額度與營業時間；不符合指定時間會提示衝突，需要使用者調整。
- 拖曳不會自動推移全部後續活動，也沒有拖曳靠近螢幕邊緣自動捲動；長距離調整可先縮小時間軸或使用詳細時間編輯。
- 實作：`ScheduleTimeCanvas.swift` / `ScheduleTimeCanvas.kt`；時間座標與手勢結果由 `ScheduleTimeEdit` 計算。

本次調整驗證：iOS 21 項 XCTest 通過；Android 26 項單元測試、5 項時間軸畫面測試及 Lint 通過。iOS 模擬器另手動驗證上把手保留結束時間、下把手保留開始時間、整塊平移保持停留長度。

## 景點工具箱與地圖搜尋

已改為左右分欄，日期移至右側時間軸上方。左側依推薦順位顯示景點與介紹入口，可拖入右欄指定時間；工具箱與時間軸各自捲動。地圖首頁與工具箱均可開啟 OSM 景點／餐飲／設施搜尋，收藏後再拖入行程。資料來源、未知費用／營業時間與 API 詳見 [POI-SEARCH.md](POI-SEARCH.md)。

### 跨欄拖曳補強

- iOS 工具箱改用直接拖動 ☰，顯示跟隨手指的景點與放置時間預覽；落點依右欄實際尺寸、捲動位置與縮放比例換算。
- 有效落點限右側時間卡片區；日期列、時間刻度、左側工具箱與日期範圍外不會觸發加入。拖到日期上停留約 0.45 秒會切換右側時間軸，兩平台均可繼續同一個拖曳手勢。
- 當日已排景點沿用原活動 ID 與停留長度；其他日期景點標示已排日期，可透過工具箱搬入目前日期，保留原活動 ID、停留長度與其他設定，不會多出副本。兩平台的鎖定景點都停用工具箱把手，仍可查看介紹。
- Android 畫面測試實際拖動既有景點後檢查沒有重複項目，並驗證其他日期與鎖定保護。iOS 加入實際畫面尺寸回報與捲動／縮放座標測試。

iOS 模擬器已手動驗證：由左欄將岩石區拖到右欄 10:35，時段從 10:08–11:18 改為 10:35–11:45，停留仍為 70 分鐘；按還原後恢復 10:08–11:18。診斷過程發現畫面快照與落點量測不同步，現改用共用拖曳狀態與即時尺寸回報，正式程式已移除診斷輸出。

### 拖曳停留日期切換（2026-10-24）

- 按住左欄景點的 ☰ 拖到日期，停留約 0.45 秒；日期外框會提示目標，切換後右欄回到該天時間軸頂端。短暫經過不會切換。
- 手指繼續移到右側指定時段才放開，依 5 分鐘格線插入或移動。僅停在日期上放開只切換顯示，不修改行程；取消拖曳會取消尚未完成的切換。
- 跨日搬動在一次操作內移除來源並插入目的日，保留 ID／停留長度與鎖定保護；「還原上一步」同時復原兩天。交通與時間衝突仍由既有試算檢查。
- Android 保持拖曳處理器穩定，在放開時讀取目前日期與最新畫面尺寸，避免日期切換中斷手勢或沿用舊落點。

驗證：iOS 28 項 XCTest 通過，包含日期停留／取消、跨日搬動與還原；模擬器另確認景點跨日後仍保留 70 分鐘停留。iOS 的自動測試驗證停留狀態與落點換算，未將其宣稱為完整觸控手勢測試。Android 27 項單元測試、11 項畫面互動測試與 Lint 通過，畫面測試包含同一觸控手勢從日期繼續拖入第二天，以及只在日期上放開不修改行程。
