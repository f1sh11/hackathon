# 地點覆蓋範圍與分類同步

2026-10-27：探索頁的地點標記來自後端整合資料，Apple Maps 底圖原生標示是另一份資料。底圖出現店名不代表它已被匯入 Zetaris；本次補充使用公開 OSM 資料，沒有將 Apple 商家資料批次複製入庫。

## 已完成的資料更新

- 本機與雲端 `sydneybuddy_travel.travel_osm_places` 都已逐筆比對 **13,510** 個地點。
- 雲端原有 5,318 筆；以既有 NSW 旅遊區域資料及藍山重新抓取結果補充，保留 573 個擴區檔案未包含的原有雪梨地點。
- 藍山三個匯入範圍共有 759 筆：住宿 78、商店 263、探索候選 178、景點 104、餐飲 136。這是有限區域資料，並非整個 NSW 或所有 Apple Maps 商家。
- 已確認 Lilianfels Hotel、Blue Mountains YHA、Katoomba Falls Tourist Park、Cafe Lurline 與 Lilianfels Park 在資料中，具有正確的分類、座標、來源及手機解碼所需欄位。
- 本機 PostgreSQL 更新採交易與備份；雲端先上傳獨立目錄，註冊測試表並逐筆核對，再透過官方檔案表設定 API 原地更新正式表的路徑，保留既有表名稱與設定。

雲端正式表目前路徑：`dffs://sydneybuddy-osm-20261027/osm-array-*.json`。舊的 `dffs://sydneybuddy-public-20261025/travel_osm_places.json` 保留，可透過檔案表設定回復路徑。此處只有公開景點資料，沒有天氣、使用者行程、帳密或權杖。

## 程式修正

- 匯入及即時 OSM 查詢涵蓋 pub、bar、nightclub、biergarten、ice_cream、自然保護區及露營住宿。
- `parks` 細分類納入 `nature_reserve`；住宿維持飯店／青年旅館／露營區的實際類型。
- 搜尋由 Zetaris 先依座標範圍篩選大型 POI／OSM 表，再交給後端合併、去重及精確距離篩選。藍山沒有 Overture 市區資料時，仍可使用 OSM 與規劃目錄。
- 公開地點匯出快取納入查詢內容指紋，分類規則改變時不再誤用舊快取。任何區域抓取失敗會停止匯出，保留既有檔案，避免部分成功就覆蓋完整資料。
- NDP 批次檔改為完整 JSON 陣列。實測此版本的多行 JSON 讀取器對 JSON Lines 每檔只讀第一筆；新打包器會驗證每個陣列檔大小，並保留所有記錄。

## 驗證與顯示上限

同一份修正版 ASP.NET Core，分別經真正本機與雲端 Zetaris 查詢 Cafe Lurline 周圍 2.5 公里，兩邊一致：

| 分類 | 回傳筆數 |
|---|---:|
| 全部 | 65（符合 487 筆，保留各分類名額） |
| 咖啡廳 | 41 |
| 住宿 | 51 |
| 飯店 | 43 |
| 青年旅館 | 6 |
| 公園 | 29 |
| 酒吧 | 5 |

探索頁最多回傳 80 筆，「全部」會保留各種分類的名額；密集區域請選細分類、輸入名稱或縮放地圖。因此底圖所有店名不會同時全部產生額外標記。

64 項後端分類／來源／範圍查詢測試通過；匯入、NDP 打包與快照相關測試另行驗證。天氣仍即時經 Zetaris 取得，沒有新增天氣快取。

## 尚待完成的 Oracle 部署

新版映像已打包，但本次 Oracle SSH 在 banner exchange 逾時，HTTPS 也無回應；Mac 鎖定使主控台狀態暫時無法查核。資料同步與本機／雲端 Zetaris API 驗證已完成，不能據此宣稱 Oracle 上的新版後端或實際手機畫面已驗證。恢復 VM 存取後需部署修正版，重跑公開 HTTPS 的分類搜尋，並檢查服務日誌與記憶體。
